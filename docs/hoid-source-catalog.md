# Hoid IA: source catalog and provenance boundary

## Purpose

This catalog defines the private bibliography that Hoid IA may use as a **source registry**. It is not a corpus dump and does not authorize copying protected text into the repository, prompts, logs, or generated fixtures.

The catalog records only bibliographic identity and high-level source boundaries. Narrative claims must still be backed by an accessible, authorized knowledge record and pass the spoiler policy for the reader's progress.

## Provenance contract

Every editorial knowledge record used by Hoid IA should preserve:

- a stable work identifier;
- a structural reading boundary, such as chapter or completed-work scope;
- an original summary or explanation rather than copied source prose;
- provenance sufficient to distinguish accessible backing from unavailable material.

A work being present in this catalog is **not** evidence that its full text is available to the runtime.

## Fail-closed rule for unavailable passages

If a requested passage or supporting section is not accessible in the current environment, Hoid IA must not:

- invent a quotation;
- claim that the passage was inspected;
- infer an unverified event as established fact;
- upgrade an unsupported recommendation into a source-backed claim.

The system may instead state the limitation, provide a clearly labeled general explanation based on already authorized records, or omit the unsupported claim.

## Spoiler and provider boundaries

Catalog membership never bypasses reading progress. Authorization remains scoped to the reader's declared progress for the specific work. Providers receive only the minimum authorized context, and provider output must pass the existing evidence and spoiler filters before presentation.

## Copyright boundary

This repository should store metadata, structural reading information, and original editorial summaries. It must not store or upload complete protected passages merely to make retrieval convenient.
