# Run 356 — interactive progress-bound character follow-up

## Objective

Turn the follow-up questions produced by Run 355 into accessible, user-controlled actions without creating a shortcut around Hoid's ordinary answer authorization path.

## Behavior

- Each reviewed follow-up is rendered as an accessible button.
- Selecting it places the exact question into the existing composer.
- Selection does not submit the question; the reader can inspect or edit it first.
- The normal send handler remains responsible for refreshing progress, resolving the reading focus, enforcing book scope, and invoking the relevant trusted/local adapter.
- The action is disabled while an answer is running or reading-progress persistence is not ready.
- The draft resolver accepts only an exact, bounded suggestion shape, a known evolution dimension, a non-empty dense citation list and safe question text.
- The resolver returns question text only; internal evidence identifiers, EPUB locators and unlock thresholds are not copied into the composer.

## Spoiler and trust boundaries

- Selecting a suggestion grants no new authorization and does not change reading progress.
- No answer is fetched or generated by the selection handler.
- The user must explicitly submit through the existing send action.
- The receiving adapter revalidates current progress, selected book scope, dossier identities, evidence unlocks and editorial annotations.
- If progress changes after selection, the ordinary answer path evaluates the question against the new progress and may return a neutral unavailable/not-found result.
- The action is local and provider-neutral.

## Validation

The dedicated workflow runs the evolution and adjacent dossier, relationship, timeline, magic and display regression suites, followed by strict TypeScript checking of the module, tests and HoidScreen integration.

## Source and copyright boundary

- No private EPUB bytes, XHTML, protected passages, source locators or narrative claims are added.
- Production character-evolution annotations remain empty until separately reviewed and promoted.
- Tests use original synthetic metadata and suggestions.
